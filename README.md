# DUO CUP

DUO CUP — турнир CS2 2×2 на Xplay. В репозитории лежат публичный сайт, панель организатора, локальный приёмник данных CS2, оверлей для OBS, оверлей поверх игры и готовые коллекции сцен.

## Где что работает

| Где | Что запустить | Адрес по умолчанию |
| --- | --- | --- |
| Сервер Linux | Сайт, панель и приём обновлений от наблюдателя в Docker | Docker на TCP 123, для зрителей `https://cup.example.com`, панель `/control` |
| ПК наблюдателя Windows | CS2, `start.cmd` и OBS | `http://127.0.0.1:8787/obs` |
| ПК наблюдателя Windows, по желанию | `overlay-cs2.cmd` для HUD прямо поверх игры | `http://127.0.0.1:8787/obs?surface=desktop` |

CS2 отправляет данные на ПК наблюдателя. Этот ПК рисует HUD для OBS и передаёт серверу данные для панели организатора. Результаты турнира хранятся на сервере. Сайт продолжает показывать сетку и результаты, если ПК наблюдателя выключен.

## 1. Запуск сайта на сервере

Нужны Git, Docker Engine и Docker Compose v2. [Установка Docker Engine](https://docs.docker.com/engine/install/) · [Установка Docker Compose](https://docs.docker.com/compose/install/linux/).

1. Клонируйте этот репозиторий с GitHub или распакуйте архив исходников. Откройте каталог, в котором лежит `compose.yaml`. URL для клонирования доступен в меню **Code** на странице репозитория.
2. Убедитесь, что TCP-порт 123 свободен на сервере. Compose по умолчанию публикует его на `127.0.0.1` для прокси на том же сервере. Если прокси находится на другой машине, задайте IP серверного интерфейса в `DUO_CUP_BIND` через `.env` и разрешите доступ к TCP 123 с адреса прокси.
3. Соберите и запустите контейнер.

   ```sh
   docker compose up -d --build
   docker compose ps
   curl -fsS http://127.0.0.1:123/api/state
   ```

4. Проверьте, что `curl` вернул JSON сетки. Контейнер слушает порт 8787 внутри Docker, а на хосте сайт доступен на TCP 123. Браузеры и Node.js `fetch` блокируют прямые HTTP(S)-запросы на этот порт, так как он зарезервирован для NTP. Для открытия сайта в браузере нужен прокси или SSH-туннель на другом порту. [Список заблокированных портов](https://fetch.spec.whatwg.org/#port-blocking).
5. Первый запуск создаёт ключи. Считайте нужный ключ на сервере и сохраните его в менеджере паролей или другом закрытом хранилище.

   ```sh
   docker compose exec -T site node -p "require('/app/runtime/keys.json').admin"
   docker compose exec -T site node -p "require('/app/runtime/keys.json').publish"
   ```

   `admin` нужен для входа в панель сервера. `publish` нужен только ПК наблюдателя. Для локального приёмника CS2 используется отдельный ключ `gsi` из локального файла.

Для зрителей, организатора и ПК наблюдателя используйте один внешний HTTPS-адрес. Обратный прокси на том же хосте принимает соединения на стандартном порту HTTPS и направляет их на `http://127.0.0.1:123`.

Например, [установите Caddy](https://caddyserver.com/docs/install) на том же хосте. Направьте DNS-имя на сервер, откройте TCP 80 и 443 и добавьте в `Caddyfile`:

```caddyfile
cup.example.com {
    reverse_proxy 127.0.0.1:123
}
```

[Документация Caddy по HTTPS](https://caddyserver.com/docs/automatic-https).

После запуска или перезагрузки Caddy откройте `https://cup.example.com/` для просмотра сетки и `https://cup.example.com/control` для управления турниром. Подставьте свой домен. Если домена пока нет, используйте SSH-туннель для репетиции.

Проверка состояния и обновление после новой версии:

```sh
docker compose logs --tail=100 site
git pull --ff-only
docker compose up -d --build
docker compose ps
```

## 2. Подключение ПК наблюдателя к сайту

На Windows установите [Node.js](https://nodejs.org/) версии 22 или новее, Steam с CS2 и [OBS Studio](https://obsproject.com/). Скачайте тот же репозиторий на этот ПК.

1. Дважды щёлкните `start.cmd` в корне проекта. При первом запуске появится папка `runtime` с локальными ключами и конфигом CS2.
2. Если окно уже запущено, остановите процесс сочетанием `Ctrl+C`. Создайте на ПК наблюдателя файл `runtime/publish.json`. Замените адрес и значение `key` на свои.

   ```json
   {
     "url": "https://cup.example.com",
     "key": "ЗАМЕНИТЕ_НА_СЕРВЕРНЫЙ_КЛЮЧ_publish"
   }
   ```

3. Снова запустите `start.cmd` и оставьте окно открытым. Откройте **панель на сервере** и войдите ключом `admin` из серверного Docker. В панели появится связь с ПК наблюдателя. Счёт и раунд появятся после подключения CS2.
4. Проверьте, что на самом ПК открывается [локальная графика OBS](http://127.0.0.1:8787/obs).

Локальная [панель на 8787](http://127.0.0.1:8787/control) использует `admin` из **локального** `runtime/keys.json`. Когда настроен мост, для управления турниром удобно работать в панели сервера.

### Подключение через SSH

Если HTTPS ещё не настроен, на ПК наблюдателя можно открыть SSH-туннель к Docker-серверу:

```powershell
ssh -N -L 9123:127.0.0.1:123 USER@SERVER
```

Замените `USER@SERVER` своим SSH-логином и адресом. Пока туннель открыт, используйте `http://127.0.0.1:9123` в `runtime/publish.json` и `http://127.0.0.1:9123/control` для входа в серверную панель. Мост принимает HTTPS и HTTP через loopback.

### Репетиция на одном ПК

Для отдельной репетиции без связи с сервером можно запустить Node.js из корня проекта с отдельной папкой данных. Закройте обычный приёмник, чтобы освободить порт 8787. В PowerShell выполните:

```powershell
$env:TOURNAMENT_DATA_DIR = Join-Path (Get-Location) 'runtime/rehearsal'
node server.mjs
```

Откройте локальную панель, войдите ключом из `runtime/rehearsal/keys.json` и скопируйте в CS2 конфиг из этой же папки. После репетиции остановите приёмник, удалите переменную командой `Remove-Item Env:TOURNAMENT_DATA_DIR` или закройте окно PowerShell. Верните конфиг из обычной `runtime` и перезапустите CS2. OBS и оверлей используют тот же локальный адрес в обоих режимах.

## 3. Данные из CS2 и матч Xplay

1. В Steam откройте свойства Counter-Strike 2, раздел «Установленные файлы», затем «Обзор». В открывшейся папке найдите `game/csgo/cfg`.
2. Скопируйте туда **с ПК наблюдателя** файл `runtime/gamestate_integration_duocup.cfg`. Перезапустите CS2. Конфиг уже содержит локальный адрес и ключ GSI. В нём должен быть адрес `http://127.0.0.1:8787/api/gsi`.
3. В Xplay создайте персональный матч со стандартным соревновательным пресетом 5×5. Поставьте по два игрока на CT и T, отключите ботов. Пятый участник заходит наблюдателем.
4. В панели сервера проверьте блок «Данные из CS2». Там видны карта, фаза, раунд и счёт CT/T. Для привязки игры к турнирной паре выберите матч и выведите его в эфир. Если реальные ники не совпадают с составами на сайте, вручную укажите, кто начинает за CT.
5. Подключите наблюдателя до первого раунда, если в итоге карты нужен полный учёт урона. Пакеты GSI приходят только во время работы игры. Урон за пропущенные раунды отмечается как неполный.

[Valve Developer Community о Game State Integration](https://developer.valvesoftware.com/wiki/Counter-Strike:_Global_Offensive_Game_State_Integration).

## 4. HUD и OBS

### Графика трансляции в OBS

1. На ПК наблюдателя откройте **Коллекция сцен → Импорт**. Для холста 1920×1080 импортируйте `obs/DUO-CUP.json`, для холста 3840×2160 — `obs/DUO-CUP-4K.json`. Размер холста устанавливается в **Настройки → Видео → Базовое разрешение**.
2. В сцене **02 · Матч CS2** откройте свойства источника **CS2 · окно наблюдателя** и выберите запущенный Counter-Strike 2. В игре используйте оконный полноэкранный режим без рамки.
3. Убедитесь, что **DUO CUP · графика матча** стоит выше захвата CS2. Для обеих коллекций браузерный источник рендерит графику в 1920×1080. Коллекция 4K масштабирует источник на весь холст.
4. В сцене **01 · Ожидание и перерыв** доступна заставка. Если настраиваете источники вручную, добавьте источники типа **Браузер** со следующими адресами.

   | Источник | URL |
   | --- | --- |
   | Графика матча | `http://127.0.0.1:8787/obs` |
   | Заставка | `http://127.0.0.1:8787/obs?scene=standby` |

5. Проверьте в микшере звук игры и источник **Комментатор · микрофон**. При двух комментаторах можно добавить отдельный источник звука приложения с голосовым чатом. Оставьте один источник на каждый сигнал, чтобы избежать эха.
6. После обновления проекта откройте свойства браузерного источника и нажмите **Обновить кэш текущей страницы**. [Справка OBS по браузерному источнику](https://obsproject.com/kb/browser-source).

### HUD поверх CS2 на экране наблюдателя

1. С работающим `start.cmd` запустите `overlay-cs2.cmd`. Первый запуск устанавливает Electron и зависимости из `desktop/package-lock.json`. Нужен интернет.
2. Зайдите в CS2 наблюдателем и держите окно игры активным. HUD появляется над окном игры, пока есть данные игроков. Положение подстраивается под окно, а клики и клавиатура передаются игре.
3. Чтобы показать или скрыть HUD, используйте `Ctrl+Shift+F10` или меню приложения в трее. Для обновления графики снова запустите `overlay-cs2.cmd` либо выберите **Обновить HUD** в трее.

Оба оверлея используют одну графику. Для эфира OBS берёт окно игры и накладывает свой браузерный источник. Если в OBS видна двойная графика, проверьте, что в сцене захватывается окно CS2, и отключите захват всего экрана.

### Игровой HUD, аватарки и камеры

Для ленты убийств из CS2 скопируйте `obs/duocup_match_hud.cfg` в `game/csgo/cfg` и выполните в консоли наблюдателя:

```text
exec duocup_match_hud
```

Конфиг скрывает дублирующий игровой интерфейс. Для возврата основного HUD выполните `cl_draw_only_deathnotices 0`. При необходимости подстройте положение ленты с помощью `safezoney`, ориентируясь на предпросмотр OBS.

Оверлей подгружает публичные аватарки Steam и показывает инициалы, если аватарка недоступна. Для своего изображения положите файл PNG, JPEG или WebP в `runtime/hud-media` на ПК наблюдателя. Создайте `runtime/hud-media.json`, используя точный игровой ник как ключ.

```json
{
  "ИгровойНик": {
    "avatar": "/hud-media/player.png",
    "camera": "https://vdo.ninja/?view=your-view-id&mute"
  }
}
```

`camera` — необязательная HTTPS-ссылка для встраивания. Если камеры нет, в центральной карточке остаётся аватарка. После изменений обновите браузерный источник OBS и HUD поверх игры.

### Twitch и проверка перед эфиром

1. В OBS подключите Twitch через **Настройки → Трансляция**. В панели турнира в разделе **Канал Twitch** сохраните публичную ссылку на канал. Для этого поля используется обычный адрес канала.
2. При необходимости установите задержку в **Настройки → Расширенные → Задержка потока**.
3. Сделайте короткую локальную запись. Проверьте стартовую заставку, захват CS2, звук, счёт раундов, миникарту, переключение наблюдаемого игрока, победу в раунде и итоги карты.
4. Перед началом эфира перепроверьте карту и стартовую сторону CT в панели. Квадраты HUD показывают выигранные карты серии. Числа рядом с таймером — раунды на текущей карте.

## 5. Проведение турнира

1. Нажмите **Начать турнир**. Первый тур сформирует четыре пары по порядку заявок. Первые три пары играют в первый день. ДимаС / Кирилл и ДимаМ / Гоша играют позже. Второй тур открывается после подтверждения всех четырёх результатов.
2. Выберите матч, задайте карты по порядку и стартовую команду CT. Нажмите **Вывести в эфир**. Когда матч уже в эфире, его карточка открывается сразу после входа в панель.
3. После каждой карты нажмите кнопку победившей команды. Счёт по картам сохраняется сразу. При счёте 1:0 в BO3 серия продолжается. Две победы в BO3 или три в BO5 автоматически сохраняют итог серии.
4. До завершения серии можно отменить итог последней карты. Вне эфира доступен ввод полного результата вручную. Сброс матча позволяет сыграть его заново, а полный сброс очищает туры, результаты и настройки эфира. Панель показывает, какие зависимые матчи затронет сброс.
5. В отборе матчи BO3. Во втором и третьем турах играют внутри групп с одинаковым счётом. В четвёртом одна команда 2:1 играет с командой 1:2, остальные играют внутри своих групп. В пятом играют команды 2:2. Три победы дают выход в плей-офф, три поражения — выбывание. При составлении пар учитываются повторы.
6. Четыре участника плей-офф сеются по числу поражений, затем по первоначальному порядку заявок. Полуфиналы #1–#4 и #2–#3 проходят в BO3. Финал — в BO5.

Перед новым турниром список команд, дату и форматы можно настроить в `dist/event.json`. После изменений соберите сайт заново и обновите копию репозитория на ПК наблюдателя. Текущий турнир хранит свои результаты отдельно.

## 6. Диагностика и резервные копии

| Симптом | Что проверить |
| --- | --- |
| Сайт не открывается в браузере | Используйте внешний HTTPS-адрес или адрес SSH-туннеля. Проверьте `docker compose ps`, логи сервиса `site` и ответ `curl -fsS http://127.0.0.1:123/api/state` на самом сервере. Если `curl` работает, проверьте DNS, прокси и доступ к TCP 80 и 443. |
| Docker не может опубликовать порт 123 из-за прав | Порт ниже 1024. При запуске Docker в режиме rootless используйте обычный Docker Engine либо настройте права на публикацию низких портов. [Документация Docker](https://docs.docker.com/engine/security/rootless/tips/#exposing-privileged-ports). |
| Панель отвергает ключ | Для панели на сервере используйте ключ `admin` из тома Docker. Для локальной панели используйте `admin` из папки данных Windows. |
| В панели «ПК наблюдателя не на связи» | Проверьте, что окно `start.cmd` работает, а `runtime/publish.json` указывает на нужный сервер и содержит серверный ключ `publish`. После исправления перезапустите приёмник. |
| В панели нет счёта или раунда | Проверьте запуск CS2 после копирования GSI-файла и наличие карты. Откройте локальный `http://127.0.0.1:8787/api/state`. При живом матче поле `gsi` равно `true`, а `game` содержит данные карты. |
| OBS показывает пустой фон или старую графику | Проверьте локальный URL в браузере, источник **DUO CUP · графика матча** и его положение выше захвата игры. Затем обновите кэш источника. |
| Кнопки победителя карты недоступны | Откройте матч в эфире и сохраните все карты в правильном порядке и сторону CT. После завершения серии доступны ручное исправление и сброс матча. |
| Текущая карта в серии отличается от карты в CS2 | В блоке «Данные из CS2» показана карта из игры, а в карточке матча — запланированная карта серии. Проверьте порядок карт до отметки победителя. |
| HUD Windows не виден | Проверьте оконный режим без рамки, наличие данных игроков и фокус окна CS2. В трее проверьте, включён ли HUD. |

Состояние и ключи хранятся в именованном томе `tournament-data`. Обычный `docker compose down` оставляет том. Перед обслуживанием сохраните архив каталога данных.

```sh
umask 077
docker compose exec -T site tar -C /app/runtime -czf - . > duo-cup-runtime-backup.tar.gz
```

В архив входят ключи. Храните его в закрытом месте. Для восстановления остановите сервис, затем распакуйте свой архив в тот же том и запустите сервис:

```sh
docker compose stop site
docker compose run --rm --no-deps -T site tar -C /app/runtime -xzf - < duo-cup-runtime-backup.tar.gz
docker compose up -d
```

На ПК наблюдателя отдельно сохраните закрытую копию `runtime/publish.json`, локальных ключей и своих файлов `hud-media`. Папка `runtime` содержит данные запуска, которые создаются на месте.
